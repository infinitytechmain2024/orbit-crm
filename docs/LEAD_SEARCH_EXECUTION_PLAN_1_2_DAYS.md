# AI Lead Search Execution Plan

Дата: 2026-08-28

Цель: за 1-2 дня довести AI-поиск лидов до состояния, где:
- пользователь запускает поиск из UI;
- AI корректно превращает запрос в фильтры;
- backend возвращает лиды в стабильном контракте;
- результаты можно сохранить в Supabase;
- saved searches можно загрузить назад;
- система не ломается на частичных ошибках и пустых ответах.

Этот план разбит на маленькие задачи, чтобы можно было выполнять их по одной, не тратя лимит на лишние итерации.

## Главные риски, которые надо закрыть

1. AI-парсер и UI должны говорить на одном контракте.
2. Backend должен возвращать одинаковую JSON-структуру всегда.
3. Supabase insert должен переживать частично пустые лиды.
4. Нужен понятный fallback, если backend, LLM или Supabase временно недоступны.
5. Долгие запросы должны показывать статус, а не просто зависать.

### День 1, блок 1: выравнивание контракта

#### Задача 1. Зафиксировать финальный контракт `SearchFilters`

Что делаем:
- проверить, нужен ли `state` как обязательный фильтр;
- если нужен, довести до него UI, AI-парсер и backend;
- если не нужен, убрать его из пути поиска, а не оставлять как полуживое поле.

Готовый промпт для следующего шага:

```text
Ты работаешь в Orbit CRM.

Задача: выровнять контракт фильтров для AI lead search.

1. Проверить тип `SearchFilters` и все места использования.

   - либо поддержать `state` end-to-end,
   - либо удалить его из рабочего контракта поиска.
4. Обновить код так, чтобы:
   - UI, AI parser, backend proxy и CRM save path использовали один и тот же набор полей;
   - не было частичных или игнорируемых полей;
   - дефолты были явными и стабильными.
5. Не менять поведение лишних экранов.

Перед правками сначала покажи, какие файлы надо менять и почему.
```

Критерий завершения:
- один контракт для фильтров;
- нет полей, которые форма отправляет, а backend игнорирует без причины;
- нет полей, которые backend ожидает, но UI не может собрать.

Что делаем:

- поддержать частичный enrichment;
- гарантировать, что пустой результат тоже валиден.

Готовый промпт:

```text

Требования:
1. Принимать фильтры поиска в едином контракте.
2. Возвращать JSON вида:
   - `leads`
   - `total`
   - `query`
```

## Definition of Done

AI lead search считается готовым, если:

- поиск стартует из UI;
- AI-парсер возвращает валидные фильтры;
- backend возвращает leads в стабильном JSON;
- `saved_searches` сохраняются и загружаются;
- CRM импорт не ломается;
- ошибка backend не роняет страницу;
- cancel и повторный поиск работают;
- можно повторить запуск локально по документу.
