## C. Завести тестовый аккаунт — это разблокирует фазу 4

Единственный невыполненный пункт плана доработок. Заводить учётные записи и
вводить пароли агент не может; со стороны кода готово всё остальное.

1. В Supabase-проекте `qavfajsflzbefgegkwjt` создайте **отдельного**
   пользователя только для e2e. Не рабочий аккаунт: тест логинится им в браузере,
   а пароль попадает в окружение процесса.
2. Заполните локальный конфиг:

   ```bash
   cp .env.e2e.example .env.e2e.local
   ```

   `AUTOPILOT_E2E_ENABLED=true`, `AUTOPILOT_E2E_EMAIL`, `AUTOPILOT_E2E_PASSWORD`,
   `AUTOPILOT_E2E_SUPABASE_ANON_KEY` (публичный anon-ключ, не service-role).
   Файл под `.gitignore` — так и должно остаться.
3. Прогоните сценарий:

   ```bash
   npx playwright test e2e/autopilot-smoke.spec.ts
   ```

   Без переменных он честно пропускается — это ожидаемое поведение, а не
   поломка. Зелёный прогон означает, что фаза 4 наконец работает целиком: до сих
   пор проверен только негативный путь (форма заполняется, Supabase отвечает
   `Invalid login credentials`, тест падает где должен).
4. **Заведите минимальные данные** под этим аккаунтом: организацию, пару
   клиентов, задачу. Иначе маршруты отрендерятся пустыми и проверка выродится в
   «страница не упала».

## E. Решения по продакшену (Render)

В `render.yaml` переменных `AUTOPILOT_*` нет вообще — в продакшене автопилот
поедет на значениях по умолчанию. Три вещи стоит решить осознанно.

### E1. Эфемерная файловая система обнуляет постоянную рабочую копию

В блюпринте нет секции `disk:`. Файловая система Render сбрасывается при деплое
и рестарте, а значит:

- голый репозиторий и `node_modules` создаются заново после каждого деплоя —
  выигрыш от кэша живёт только внутри одного запуска инстанса;
- **`_resume_delivery` не переживёт рестарт**: если процесс перезапустится между
  неудавшимся push и повторной попыткой, коммит исчезнет вместе с диском.

Варианты: подключить Render Disk (заложите с запасом — на каждый слот полный
чекаут плюс `node_modules`) либо сознательно принять деградацию: всё продолжит
работать, просто медленнее и без возобновления доставки через рестарт.

### E2. Слотов меньше, чем воркеров

`AI_WORKFLOW_WORKER_CONCURRENCY=4`, а `AUTOPILOT_WORKSPACE_SLOTS` по умолчанию
`2`. Под нагрузкой два из четырёх параллельных ранов откатятся на одноразовый
клон. Это штатное поведение, не сбой; если хотите постоянную копию для всех —
поднимите слоты до 4 и заложите место на диске.

### E3. Браузерный самотест на starter-плане, скорее всего, не поедет

Фаза 4 поднимает Vite dev server и Chromium. Инстанс Render starter для этого,
по всей видимости, мал по CPU и памяти — **проверьте фактические лимиты вашего
плана перед включением**. Если не хватает, автопилот не ломается: верификация
вернёт `skipped`/`error`, PR всё равно откроется.

Практичный вариант: держать `AUTOPILOT_E2E_ENABLED=false` в продакшене, а
браузерную проверку гонять локально или в CI, где ресурсов достаточно.
