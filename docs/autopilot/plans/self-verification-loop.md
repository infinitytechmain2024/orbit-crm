# Autopilot plan — планировщик и верификатор жизненного цикла задачи

Задача: превратить `coding_executor` из «одношагового исполнителя» в полный
жизненный цикл: план → исполнение с трекингом → самопроверка кода →
E2E-самотест в браузере → итоговый отчёт.

Статусы: `[ ]` не сделано · `[x]` сделано · `[!]` заблокировано (причина рядом).

## Фаза 1. Планирование

- [x] 1.1 Модуль `backend/services/autopilot_plan.py`: модель плана (шаги с id,
      заголовком, статусом, заметкой), рендер и парсинг Markdown-файла плана.
- [x] 1.2 Генерация плана моделью до начала работы; файл плана пишется в
      рабочую копию по фиксированному пути `docs/autopilot/plans/<task-id>.md`
      и попадает в тот же PR.
- [x] 1.3 Fallback: если модель не вернула валидный план — детерминированный
      план из критериев приёмки, run не падает.

## Фаза 2. Исполнение с трекингом прогресса

- [x] 2.1 Инструменты `complete_step` / `block_step` / `show_plan` в цикле
      исполнителя; каждое обновление немедленно переписывает файл плана.
- [x] 2.2 Блокировка шага не останавливает run: причина фиксируется, агент
      продолжает независимые шаги.
- [x] 2.3 План и его текущие статусы попадают в system prompt исполнителя.

## Фаза 3. Итоговая ревизия кода

- [x] 3.1 Модуль `backend/services/autopilot_verifier.py`: ревью по реальному
      `git diff` (а не по «воспоминаниям» модели), строгий JSON-ответ.
- [x] 3.2 Ограниченный цикл починки: findings уровня blocker/major
      возвращаются исполнителю с теми же инструментами.
- [x] 3.3 Непочинённые findings уходят в тело PR и в отчёт, а не теряются.

## Фаза 4. Автономная проверка в браузере (E2E self-test)

- [x] 4.1 Playwright-сценарий `e2e/autopilot-smoke.spec.ts`: логин локальным
      тестовым аккаунтом + проход по ключевым маршрутам + проверка отсутствия
      фатальных ошибок в консоли.
- [x] 4.2 Учётные данные только из окружения (`E2E_EMAIL` / `E2E_PASSWORD`),
      файл `.env.e2e.local` не коммитится; в репозитории только `.env.e2e.example`.
- [x] 4.3 Запуск Playwright из верификатора: секреты через env, argv чистый,
      вывод скрабится от секретов перед сохранением в отчёт.
- [x] 4.4 Провал E2E не роняет PR — он помечает верификацию как failed и
      передаёт дефекты в QA-фазу.

## Фаза 5. Итоговый отчёт

- [x] 5.2 Отчёт — тело PR; структурированные данные — в `CodingExecutionResult`

## Дефекты, найденные самопроверкой этой же ветки

Фаза 3 применена к собственному диффу. Найдено и починено:

1. `AUTOPILOT_E2E_SUPABASE_ANON_KEY` не проверялся в гейте — полунастроенное
   окружение падало внутри браузера («Supabase не настроен») вместо честного
   `skipped`.
2. `playwright.config.ts` жёстко указывал `http://localhost:8080`, поэтому
   `E2E_BASE_URL` передавался в процесс теста и игнорировался; заодно прогон
   верификации мог переиспользовать чужой dev-сервер и проверить не тот код.
   Порт по умолчанию для автопилота разведён на 8099.
3. Дефолтный таймаут Playwright (30 с) срабатывал раньше 45-секундных ожиданий
   логина — бюджет был недостижим. Добавлен `test.describe.configure`.
4. Файл плана был защищён только формулировкой промпта. Модель могла
   переписать его через `write_file` и отметить шаги сделанными, не сделав их;
   теперь путь защищён в `_is_protected`, как `.git` и `.env*`.
5. `playwright-report/` и `test-results/` были в индексе git — каждый прогон
   верификации пачкал бы ветку, которую проверяет. Убраны из отслеживания.
