# OpenClaw integration (интеграция OpenClaw)

## Поток запроса

1. Browser (браузер) отправляет Supabase access token (токен доступа) в server route (серверный маршрут) Orbit CRM.
2. Server route передаёт пользовательский токен в `X-Supabase-Authorization`, а `INTERNAL_API_TOKEN` — в `Authorization` FastAPI.
3. FastAPI проверяет обе стороны, membership (членство) и permission (право) организации.
4. Backend загружает только tenant-scoped context (контекст текущей организации) и вызывает agent `main` OpenClaw.
5. Результат возвращается как draft/recommendation (черновик/рекомендация). Внешнее действие автоматически не выполняется.

## Доступный контекст

Поддерживаются entity types (типы сущностей): client/lead, task и calendar_event. Контекст ограничивается настройкой `OPENCLAW_MAX_CONTEXT_RECORDS`; также добавляются недавние взаимодействия, открытые сделки, каталог базы знаний и результаты. Сущность `deal` присутствует в схеме, но OpenClaw-действия для неё намеренно отключены до утверждения бизнес-модели сделок.

Разрешённая область интеграции:

| Сущность | Чтение контекста | Разрешённые рекомендации | Запись в CRM |
|---|---|---|---|
| client/lead | Карточка, взаимодействия, открытые сделки, результаты | Черновик сообщения, следующий шаг, резюме | Нет |
| task | Карточка, чек-лист, комментарии, метаданные файлов | План, следующий шаг, резюме, QA review (проверка качества) | Нет |
| calendar_event | Карточка события | Следующий шаг, резюме | Нет |
| deal | Отключено | Отключено | Нет |

Содержимое файлов и `storage_path` (путь в хранилище) не передаются OpenClaw. Каждый запрос `/assist` записывается в `ai_action_audit` (журнал действий AI).

## Контролируемые действия

- `draft_message` — подготовить сообщение, отправка только человеком.
- `next_action` — предложить следующее действие.
- `summarize_history` — подготовить сводку истории.
- Knowledge proposal (предложение базы знаний) — применяет owner/admin; сохраняется версия.
- Rollback (откат) — выполняет owner/admin, история не удаляется.

Запрещены автоматические: удаление данных, смена ролей, изменение production-кода, подключение платных сервисов, массовая отправка, изменение финансовых условий и публикация конфиденциальных данных.

## Отказоустойчивость

OpenClaw расположен отдельно от CRM. Timeout/rate limit (тайм-аут/лимит частоты) и daily action cap (дневной лимит действий) ограничивают расходы. Ошибка провайдера скрывается от клиента и записывается сервером. При недоступности OpenClaw основные Supabase CRUD (операции создания/чтения/изменения/удаления) продолжают работать.
